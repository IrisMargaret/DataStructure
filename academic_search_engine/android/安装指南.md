# 学术论文检索系统 · Android APK 安装与使用指南

本文档说明如何安装、使用与重新构建 Android 版《学术论文关键词索引与检索系统》。

## 0. 版本说明（修复"白屏打不开"）

v1.0 曾出现「安装后打开一直白屏/黑屏」的问题，根因是**首次启动耗时长于 30 秒等待上限**：
首次启动要解压内置 Python 运行时、加载 jieba 词典并对预置论文建索引，中端手机上可能超过 30 秒，
超时后只弹一个短暂的 Toast，界面停在白屏，看起来像"打不开"。

**本版本（AcademicSearchEngine-debug.apk）已修复**：
- 打开 App 立即显示「正在启动本地检索服务…」加载动画（不再白屏）；
- 服务等待上限 30 秒 → **180 秒**；
- 若启动真正失败，把**详细错误显示在屏幕上**（不再只有一闪而过的 Toast），
  并写入 App 私有目录 `startup-error.log`，便于反馈定位。

## 1. 快速开始（安装 APK）

交付物：`android/AcademicSearchEngine-debug.apk`（约 85 MB，含内置 CPython 3.12 与全部检索算法）。

**安装步骤（安卓手机）：**

1. 把 `AcademicSearchEngine-debug.apk` 传到手机（数据线 / 微信文件传输 / 网盘均可）；
2. 点击 APK 文件，系统提示「未知来源应用」时选择 **允许**（不同厂商入口略有差异：设置 → 安全 → 允许安装未知应用）；
3. 安装完成后桌面出现 **「学术论文检索」** 图标。

> 说明：debug 版 APK 使用本地调试签名，仅用于个人安装演示；商店分发需另行 release 签名。

## 2. 首次启动

1. 打开 App，先看到「正在启动本地检索服务…」加载页（首次约 10 秒 ~ 1 分钟，请耐心等待）；
2. 服务就绪后自动进入检索主界面；
3. 若显示「启动失败」红底错误页，请把页面内容截图反馈（或按 §5 抓取 `startup-error.log`）；
4. 无需联网即可使用：**检索、文库浏览、中英互译、前缀补全、去重入库、原文查看（已归档文件）** 全部离线可用；
5. 需要联网的功能：爬取 arXiv / OpenAlex、LLM 元数据精修（需自行配置密钥）、外部原文链接跳转。

**内置数据**：预置论文元数据 `papers.json`（含题目/摘要/作者/关键词），首启解压到 App 私有目录，后续在 App 内上传的论文会持久保存在手机里。

> 注意：为控制包体，未打包原论文 PDF（约 31 MB）。因此库内元数据完整可检索，但 4 篇已归档 PDF 的「阅读原文」在手机上不可用（会提示无原文文件）。在手机上**新上传**的 PDF/TXT/ZIP 仍可正常阅读。

## 3. 界面操作（手机端）

| 功能 | 位置 | 说明 |
|---|---|---|
| 检索 | 首页「索引检索」 | 多词 AND、布尔、引号短语、中英互译开关均可用 |
| 文库 | 侧栏「文库」 | 浏览/过滤/详情/删除；上传按钮弹出系统文件选择器 |
| 上传论文 | 文库 → 动态添加 | 支持 PDF / TXT / ZIP / arXiv URL / 手动填写 |
| 阅读原文 | 论文详情 | 上传过的文件自动下载并用系统查看器打开 |
| 外链 | 标题链接 | arXiv / DOI 链接用系统浏览器打开 |

**WebView 细节**：
- 页面目标为 `_blank` 的链接（外链、原文）已做桥接：外链走系统浏览器，原文走应用内下载；
- 返回键：先回退页面历史，再退出 App。

## 4. 重新构建 APK（开发者）

### 4.1 环境要求（本机已验证）

| 组件 | 版本 |
|---|---|
| JDK | 17（`JAVA_HOME` 指向含 `keytool` 的 JDK） |
| Android SDK | platform android-36、build-tools 36.x（`android/local.properties` 的 `sdk.dir` 指向 SDK） |
| Gradle | 9.1.0（wrapper 或系统安装；本机验证用缓存发行版） |
| Python（构建期） | 3.12，路径写在 `android/app/build.gradle` 的 `python.buildPython` |
| 网络 | 需访问 Maven Central / Google Maven / PyPI / chaquo.com（首次构建下载依赖） |

### 4.2 一键构建

```bat
cd android
build_apk.bat          :: 或 PowerShell: .\build_apk.ps1
```

脚本会依次执行：

1. `sync_android.ps1`：把 `core/service/web/ingest/crawler/agent` 及 `logutil.py` 同步到 `app/src/main/python/`，把 `templates/static/data`（词典与元数据，**不含** 31 MB 论文 PDF）同步到 `app/src/main/assets/academic/`；
2. Gradle `:app:assembleDebug`。

产物：`app/build/outputs/apk/debug/app-debug.apk`。

### 4.3 构建机制说明（关键）

| 机制 | 说明 |
|---|---|
| **Chaquopy 17.0.0** | 在 APK 内嵌 CPython 3.12 运行时，`mobile_server.py` 于 App 私有目录启动 Flask（`127.0.0.1:8765`），WebView 加载首页，前端零改动 |
| **数据目录重定向** | 源码各模块读取 `ACADEMIC_DATA_ROOT` 环境变量（`mobile_server.start` 注入），指向 `filesDir/academic`，保证 APK 内只读资源目录不被写入 |
| **jieba 本地 wheel** | jieba 在 PyPI 仅有 sdist，而 Chaquopy pip 强制 `--only-binary`；故将预构建 wheel 放 `android/local-wheels/`，以 `--find-links` 提供 |
| **sitecustomize 注入** | `android/sitecustomize.py` 由 Gradle 任务 `injectSitecustomize` 在 pip 安装前注入构建 venv，规避 Windows 沙箱对 `0o700` 目录的 ACL 限制（pip 解包用 `mkdtemp(0o700)`） |
| **debug 签名** | keystore 放项目内 `app/debug.keystore`（`android` / `androiddebugkey`），避免写系统 `~/.android` |
| **ABI** | `arm64-v8a` + `x86_64`（Chaquopy 17 + Python 3.12 不支持 armeabi-v7a） |

> 若在普通 Windows（无沙箱）上构建，可移除 `sitecustomize` 注入与 `local-wheels` 的 `--find-links`（jieba 改为允许 sdist 的镜像）——但保留也无害。

## 5. 已知限制与后续路线

| 限制 | 说明 / 出路 |
|---|---|
| 包体 ~61 MB | 内含两套 ABI 的 CPython；只保留 `arm64-v8a` 可再减约 1/3 |
| 未内置 31 MB 原文 PDF | 需要时执行 `sync_android.ps1` 前把 `data/papers_files` 拷入 assets 并改 MainActivity 解压逻辑 |
| iOS 不支持 | 本方案为 Android APK；iOS 需另走 Capacitor + 远程后端（见总规划 M4） |
| LLM 精修需密钥 | 手机端未带 `.env`；如需可在 App 私有目录放置 `.env` 后重启 |

## 6. 手机连电脑排障（USB 数据线 + adb）

**问题：什么线能连？**
- 必须是**支持数据传输**的 USB 线（能传文件/充电的线，两端都是数据线）。只用于充电的"纯电源线"（常见于部分廉价充电线、某些充电宝赠线）**不能**传数据。
- 电脑通常无需装驱动（Windows 10/11 自动识别）；若手机连上后电脑无反应，先换线、换 USB 口再试。

**步骤（荣耀等安卓手机）：**

1. 手机开启 **开发者选项**：设置 → 关于手机 → 连续点击「版本号」7 次（提示已进入开发者模式）；
2. 设置 → 系统和更新 → 开发者选项 → 打开 **USB 调试**；
3. 用数据线连接手机与电脑，手机上弹窗「允许 USB 调试吗？」→ 勾选始终允许 → 确定；
4. 电脑上确认连接：命令行执行

   ```
   adb devices
   ```

   出现 `xxxxxxx device`（而不是 `unauthorized`/空）即成功。

**抓取 App 日志（排障用）：**

```
adb logcat -s AcademicSearch AndroidRuntime Python native.stdout native.stderr
```

打开 App 复现问题后按 `Ctrl+C` 停止，把输出发给我即可精确定位。
也可直接抓 App 私有日志文件（App 启动失败时已写入）：

```
adb shell "run-as com.academic.search cat files/academic/startup-error.log 2>/dev/null || echo no-log"
adb shell "run-as com.academic.search ls -R files/academic 2>/dev/null"
```

> 若 `adb` 不在 PATH：使用 `C:\Users\marym\AppData\Local\Android\Sdk\platform-tools\adb.exe`。
